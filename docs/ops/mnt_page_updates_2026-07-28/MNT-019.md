# MNT-019 — BarsCalculated-Probe ohne falschen T5-Kontrollarm

Autor: Codex  
Korrigiert nach Review Claude 2026-07-28

## Problem

Das bisherige A/B-Design besitzt keinen gültigen Kontrollarm. Das
instrumentierte QM5_20096 zeigte bei gültigen Handles wiederholt
`BarsCalculated=-1` auf den gesunden Terminals T2, T3 und T10
(`STRATEGY_DIAG`, unter anderem `h_sma=10`, `h_sto=11`, `bc=-1`,
`bars=2366+`) und lief nie auf T5. Eine T5-spezifische Ursache lässt sich daraus
nicht ableiten.

Auch QM5_11144 ist keine gesunde Kontrolle: im DB-Snapshot hatte es in Q02
6×`INFRA_FAIL`, 3×`ZERO_TRADES`, 1×`FAIL`, 4×NULL und keinen einzigen PASS.
„Gesunder PASS gegen T5-FAIL“ ist damit nicht konstruierbar. Positive
BarsCalculated-Kontrollen existieren dagegen bei QM5_11912 und QM5_20102
(Q02-PASS im selben Problemumfeld).

Weil der Fehler terminalübergreifend auftritt, ist der wahrscheinlichste Ast
die gemeinsame Framework-Strecke. Hauptverdacht ist der Handle-Cache in
`framework/include/QM/QM_Indicators.mqh`: Lookup/Register um Zeile 63/71,
iMA-Erzeugung und Registrierung um 274–278 sowie iStochastic um 448–452. Ein
noch nicht bereiter Handle kann wiederverwendet werden, bevor
`BarsCalculated` positiv ist. Ein kompletter T5-Instanz-Rebuild ist daher kein
begründeter nächster Schritt.

## Lösungsvorschlag

1. Keine neue T5-Ausführung. Die Probe wird auf vorhandenen gesunden
   Terminals mit QM5_11912 oder QM5_20102 als positivem Kontroll-EA aufgebaut.
2. Instrumentierung protokolliert pro Handle: Cache-Hit/Miss, Erzeugungszeit,
   Handle-ID, `BarsCalculated`, `GetLastError`, Symbol/Timeframe und den ersten
   erfolgreichen Buffer-Read.
3. Testmatrix: positiver Kontroll-EA und Offender auf demselben Terminal sowie
   derselbe Offender auf mindestens zwei bereits gesunden Terminals.
4. Wenn ein Cache-Hit einen nicht bereiten Handle liefert, muss Lookup entweder
   Bereitschaft prüfen oder den Handle kontrolliert neu erzeugen. Keine
   Strategiebedingung wird verändert.
5. Erst wenn der Fehler mit positiver Kontrolle ausschließlich auf einem
   Terminal reproduziert ist, darf eine terminalbezogene Reparatur geplant
   werden; dieser Nachweis liegt für T5 nicht vor.

## Akzeptanzkriterien

- Die Kontrolle besitzt vor Beginn nachweislich mindestens einen Q02-PASS und
  einen positiven `BarsCalculated`-Pfad; QM5_11144 ist ausgeschlossen.
- Die Matrix enthält T2/T3 oder T10, aber startet oder aktiviert T5 nicht.
- Logs unterscheiden Cache-Hit, Cache-Registrierung, Handle-Bereitschaft und
  Buffer-Read eindeutig.
- Ein Framework-Fix besitzt eine Regression, die keinen Handle aus dem Cache
  als verwendbar meldet, solange `BarsCalculated <= 0` ist.
- Eine Terminal-Reparatur wird nur mit einem echten
  „Kontrolle PASS / Offender FAIL auf genau diesem Terminal“-Nachweis
  freigegeben.
