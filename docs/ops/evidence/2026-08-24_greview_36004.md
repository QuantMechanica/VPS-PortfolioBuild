### 3. TP1 is recomputed from rolling ATR instead of being bound at entry

The card fixes TP1 at +1.0 ATR and SL at -1.0 ATR (`approved card:96-99`). Entry binds the SL from ATR at signal time (`...mq5:302-322`), but management later recomputes `ATR[1]` on every tick and uses that changing value as the partial-close trigger (`...mq5:344-374`). A multi-day trade can therefore receive a TP1 distance different from the approved entry-time ATR/1R distance.

Required fix: bind the TP1 distance at entry (or derive the original 1R distance from durable position data before BE), and keep that distance invariant for the trade.

### 4. The EA invents an ALMA runner exit not present in the approved card

The approved exit contract says `Runner Exit: QQE signal cross` (`approved card:96-99`). The EA additionally closes a long when Close falls below ALMA and a short when Close rises above ALMA (`...mq5:391-418`). `SPEC.md:27` repeats this extra behavior, but SPEC cannot broaden the approved Strategy Card.

Required fix: remove the ALMA exit and retain the approved QQE flip, unless an OWNER-authorized card revision explicitly changes the exit contract before rebuild.

### 5. Default risk inputs are mutually exclusive but both enabled

The EA declares `RISK_PERCENT=0.5` and `RISK_FIXED=1000.0` simultaneously (`...mq5:18-21`). `QM_FrameworkValidateRiskInputs` fails initialization when both are positive (`framework/include/QM/QM_Common.mqh:166-177`). The four backtest setfiles correctly override this to `RISK_FIXED=1000` / `RISK_PERCENT=0` (for example `.../sets/...EURUSD.DWX_D1_backtest.set:33-41`), but the EA has no valid percent-mode default for live use as required by `SPEC.md:102-110`.

Required fix: make the source/live default percent-only (`RISK_FIXED=0` with the approved live percent), while preserving fixed-only values in governed backtest setfiles.

### 6. QQE dynamic buffer is neither bounded to card ranges nor resize-guarded

`warmup` and `n` are derived from user inputs, then `ArrayResize(rsi_ma, n)` is unchecked before indexed writes/reads (`...mq5:98-108,110-165`). There is no OnInit validation of the card ranges and no `ArrayResize` result / `ArraySize` guard. This does not satisfy the requested bounded-indicator-buffer contract even though the current static D10 heuristic reports zero failures.

Required fix: validate QQE inputs against the approved ranges, cap the allocation, require successful resize/`ArraySize >= n`, and fail closed before indexing.

### 7. Card slippage limit is not bound, and the raw-series performance annotations are not true on the exit path

- The card caps market-order slippage at 3.0 ticks (`approved card:111-114`). The EA supplies no slippage input or tick-to-point conversion. `QM_FrameworkInit` configures entry deviation to a literal 20 points (`framework/include/QM/QM_Common.mqh:296-298`; `framework/include/QM/QM_Entry.mqh:63-68,88`). There is therefore no evidence that the card's three-tick cap is enforced.
- Every raw `iClose/iHigh/iLow/iVolume` call has a `perf-allowed` comment (`...mq5:82,192,211-217,287,397`), so the annotation-presence check passes. However, the ALMA/QQE exit calculation runs before `QM_IsNewBar()` on every tick (`...mq5:452-484`), contradicting the comments that the raw series work is behind the new-bar gate.

Required fix: bind the three-tick limit through a correct tick-size-to-point conversion, and gate closed-bar signal/exit calculations once per D1 bar while leaving protective position management reachable on every tick.

### 8. Partial-close transition is not idempotent if BE modification fails

After a successful 50% partial close, the EA attempts to move SL to BE but records no durable TP1-complete state (`...mq5:369-386`). If `QM_TM_MoveSL` fails, `sl_not_breakeven` remains true and a later tick can partial-close half of the remainder again, violating the card's single 50% TP1 lifecycle (`approved card:96-99,118-153`).

Required fix: persist/reconstruct the TP1-complete transition independently of the BE modification and retry only the BE move, never the partial close.
