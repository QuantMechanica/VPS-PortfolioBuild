### 3. Stop placement changes the approved swing-plus-3-pip stop

The card requires the stop beyond the recent H1 swing extreme by 3.0 pips and
the TP at exactly 2R (`approved card:96-99`). The EA first builds that stop, but
then imposes a non-card `0.5 * ATR` minimum and replaces a nearer valid stop
(`MQ5:202-224`). This changes the stop, risk-sized volume, and TP. The fallback
at `MQ5:196-197` also invents a manual `point * 10` conversion rather than
failing closed if the governed pip helper cannot provide a distance.

**Named fix:** define the exact “recent swing” selection in the approved card,
then implement swing extreme plus/minus 3 pips without the ATR substitution;
fail closed if pip conversion cannot be resolved.

### 4. H1 state, exits, and admission are not safely refreshed

- All indicators use `strategy_signal_tf=PERIOD_H1` (`MQ5:36`, `:95-126`), but
  the bar gate is parameterless `QM_IsNewBar()` (`MQ5:388`). The helper defaults
  to `_Period` (`framework/include/QM/QM_Indicators.mqh:142-152`), so a non-H1
  chart controls H1 signal refresh.
- `Strategy_ManageOpenPosition()` runs before state refresh (`MQ5:350-360`),
  while `AdvanceState_OnNewBar()` runs only after news, new-bar, and no-trade
  returns (`MQ5:376-395`). TDI exits and BE therefore use prior cached values;
  after initialization they remain zero until that late path runs.
- `Strategy_NoTradeFilter()` is evaluated before state refresh (`MQ5:391-395`).
  On startup `g_last_atr=0` (`MQ5:64`), so the spread check is skipped
  (`MQ5:163-168`), after which the same tick may populate a signal and enter.

**Named fix:** bind new-bar tracking explicitly to
`(_Symbol, strategy_signal_tf)`, seed/refresh and validate closed-H1 state before
management and admission, clear caches on failed reads, and keep entry-only
blackouts from suppressing exit/management evaluation.

### 5. Approved three-tick slippage ceiling is absent

The card requires maximum slippage of 3.0 ticks (`approved card:111-115`). The
EA exposes no slippage input and makes no `QM_EntryConfigure` call after
framework initialization. `QM_FrameworkInit` configures the entry layer with
literal deviation `20` (`framework/include/QM/QM_Common.mqh:296-298`), stored
as entry deviation points (`framework/include/QM/QM_Entry.mqh:63-88`).

**Named fix:** bind an approved, correctly unit-converted three-tick maximum to
the governed entry configuration; do not silently use the framework's 20-point
default.

### 6. Card adjudication is still required for invented/incomplete management

The card does not define how many bars constitute “recent swing,” nor a numeric
BE trigger, while the EA invents a 5-bar lookback (`MQ5:43`, `:120-131`) and a
1R BE trigger (`MQ5:47-48`, `:271-295`). The card's lifecycle diagram says BE
moves the stop to “Entry + 1” and includes a trailing-stop state
(`approved card:118-153`); source moves it by two points and implements no
trailing state. The TDI “crosses back” exit is implemented only as present
fast/slow ordering (`MQ5:256-269`), with no explicit cross-state contract.

**Named fix:** have the card owner specify swing selection, BE level/trigger,
trailing behavior (or explicit absence), and cross-back semantics; implement
only the approved deterministic mechanics.
