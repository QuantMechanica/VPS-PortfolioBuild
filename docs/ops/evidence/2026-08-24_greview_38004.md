## Actionable defects

### 1. First eligible bar can bypass the spread ceiling

The spread contract is `spread > 1.8 * ATR(14)[1]` (`card:83-86`). `g_strategy_cached_atr` starts at zero (`mq5:55`) and the spread filter only applies when that cache is already positive (`mq5:131-140`). `OnTick` runs `Strategy_NoTradeFilter()` before the new-bar gate and before `Strategy_EntrySignal()` (`mq5:352-353,384-391`), while ATR is first populated inside `Strategy_EntrySignal()` (`mq5:173-177`). Therefore the first eligible closed bar after init/restart can populate ATR and enter without re-evaluating the spread ceiling.

**Named repair:** populate/validate the closed-bar ATR before entry admission, or re-evaluate the spread condition after the indicator read and before emitting the entry request. Keep management and hard exits reachable ahead of entry-only filters. Add a regression test that starts with an empty ATR cache and an over-limit spread and proves no order request is emitted.

### 2. Card's three-tick deviation ceiling is not wired

The card declares maximum slippage tolerance of 3.0 ticks (`card:111-115`). The EA exposes no slippage/deviation input and passes no deviation into `QM_FrameworkInit` (`mq5:11-50,314-329`). The shared legacy initialization calls `QM_EntryConfigure(..., 20, ...)` (`QM_Common.mqh:296-297`), and the entry layer sends that value as request deviation (`QM_Entry.mqh:63,68,88,462`). This is a 20-point framework default, not an explicit card-bound three-tick conversion.

**Named repair:** wire the card's three-tick maximum through the governed framework entry configuration using symbol tick-size/point conversion, with a static/unit assertion for the effective request deviation. Do not invent a different tolerance.

### 3. Governed setfiles predate the current input contract

The three required setfiles are present and the Gemini summary lists them under `setfiles_generated`. They have correct symbols/slots and fixed backtest risk. However, their only commit is `8269f225e` dated 2026-08-18, while the MQ5 was changed by `6fdb5b310` (2026-08-23) and `20425871d` (2026-08-24). They omit the current loss-limit inputs at `mq5:48-50`; their headers still say 2026-08-17 and their strategy block ends at `strategy_spread_filter_mult` (`setfiles:23-35`). The governed generator automatically emits every `strategy_*` input default (`framework/scripts/gen_setfile.ps1:638-669`), so the present files are not regenerated from the current source contract.

**Named repair:** after the source repair, regenerate all three backtest setfiles using `framework/scripts/gen_setfile.ps1`/the governed setfile path and retain `RISK_FIXED=1000`, `RISK_PERCENT=0`, and slots 0/1/2.
