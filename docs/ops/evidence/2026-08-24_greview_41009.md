## Verdict basis — actionable defects

### 1. Source defaults make the framework fail initialization

The EA declares both `RISK_PERCENT=0.5` and `RISK_FIXED=1000.0` as positive
defaults (`QM5_41009_volume-profile-value-area-rejection.mq5:18-20`) and passes
both to `QM_FrameworkInit` (`:388-391`). The framework explicitly rejects this
combination in `framework/include/QM/QM_Common.mqh:166-177`, with the check
enforced at `:220-221`.

Both governed backtest setfiles correctly override this to
`RISK_FIXED=1000` / `RISK_PERCENT=0` (`sets/*_backtest.set:19-20`), but a Q02
build must not have invalid source defaults and live must use the inverse
single-mode binding. **Fix:** make the default/backtest contract fixed-only;
use a separately governed live setfile with percent-only risk.

### 2. Three approved loss-limit mechanisms are missing

The card requires a 2.0% daily realized-loss entry halt
(`card:82-87`), a 2.5% daily hard stop, and a 5.0% total-drawdown stop
(`card:110-113`). `Strategy_NoTradeFilter` contains only spread and clock
checks (`mq5:251-268`), and no matching loss-limit inputs or strategy logic
exist. The generic framework initialization is not equivalent: it configures
3.0% daily and 0.0% portfolio drawdown
(`framework/include/QM/QM_Common.mqh:296-299`).

The read-only `build_gate_hardening.py` invocation returns three independent
`EA_CARD_LOSS_LIMIT_MISMATCH` failures. **Fix:** implement and test all three
card values as executable, restart-safe controls without changing the card
thresholds.

### 3. GMT blackout is evaluated in raw broker time

The card specifies `23:55`-`00:05` GMT (`card:82-86`), while the EA applies
those hour/minute literals directly to `TimeCurrent()` (`mq5:262-265`). The
read-only hardening gate returns
`EA_BROKER_TIME_USED_FOR_GMT_WINDOW`. **Fix:** convert broker time with the
governed DST-aware `QM_BrokerToUTC` path before evaluating the approved window.

### 4. The M5 execution contract is undeclared

The card binds the strategy to M5 (`card:37-39`, `:219-224`), but profile,
ATR, and signal reads use `PERIOD_CURRENT` (`mq5:95-151`, `:257-258`,
`:277-287`). `OnInit` initializes and logs success without calling
`QM_FrameworkDeclareExecutionContract` (`mq5:386-395`). The framework contract
is explicitly intended to be called after init and rejects a timeframe
mismatch (`framework/include/QM/QM_Common.mqh:470-500`). **Fix:** declare
`PERIOD_M5` and the explicit Friday-close contract in `OnInit`, failing init on
mismatch.

### 5. Wrong-side POC setups use an unapproved 1.8R exit

The sole approved take-profit mechanic is the previous-day POC
(`card:95-98`). When POC is not beyond entry, the EA substitutes 1.8R
(`mq5:298-302`, `:315-319`). This changes the tested strategy. **Fix:** fail
closed on a wrong-side POC, or obtain a separately approved card change before
implementing a fallback; do not silently substitute another target.

### 6. Approved three-tick slippage is not configured

The card caps market-order slippage at three ticks (`card:110-113`). The EA
does not call `QM_EntryConfigure`; generic framework init supplies 20 points
(`framework/include/QM/QM_Common.mqh:296-297`,
`framework/include/QM/QM_Entry.mqh:63-88`). Points and ticks are not generally
the same unit. **Fix:** convert the approved three ticks through symbol tick
size/point and bind the resulting deviation through the governed entry helper.

receipt is
