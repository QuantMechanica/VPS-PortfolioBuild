### F3 — “daily realized loss” is implemented as equity drawdown

The approved card requires an entry halt when **daily realized loss** reaches 2.0% (`D:/QM/strategy_farm/artifacts/cards_approved/QM5_35005_sma-crossover-pullback-system.md:83-88`). `StrategyDailyEntryHalt()` instead compares current `ACCOUNT_EQUITY` with `g_qm_ks_day_start_equity` (`framework/EAs/QM5_35005_sma-crossover-pullback-system/QM5_35005_sma-crossover-pullback-system.mq5:72-82`). Account equity includes unrealized P&L, including P&L from other EAs, so this is not the declared realized-loss mechanic.

The separate 2.5% daily and 5.0% total equity hard stops are correctly wired through `QM_KillSwitchInit` (`framework/EAs/QM5_35005_sma-crossover-pullback-system/QM5_35005_sma-crossover-pullback-system.mq5:234-238`); they do not make the 2.0% realized-loss entry rule equivalent.

**Named fix:** calculate the card's 2.0% daily realized loss from closed-deal history over the governed trading-day boundary, with the intended EA/magic scope made explicit, while retaining the existing hard-stop kill-switch wiring unchanged.

### F4 — card's maximum 3-tick entry slippage is not wired

The approved card caps market-order slippage at 3.0 ticks (`D:/QM/strategy_farm/artifacts/cards_approved/QM5_35005_sma-crossover-pullback-system.md:111-115`). The EA exposes no slippage input or configuration call. `QM_FrameworkInit` configures entries with the framework literal `20` deviation points (`framework/include/QM/QM_Common.mqh:296-298`), and `QM_EntryConfigure` retains that value (`framework/include/QM/QM_Entry.mqh:63-88`).

**Named fix:** wire the card's 3-tick maximum through the governed entry configuration, converting ticks to broker deviation points using symbol tick-size/point semantics where necessary. Do not change the card threshold.

The card specifies 23:55 through 00:05 GMT (`D:/QM/strategy_farm/artifacts/cards_approved/QM5_35005_sma-crossover-pullback-system.md:83-87`). **Named fix:** express the upper boundary so the entire documented 00:05 minute is blacked out (for example, `< 0006` for minute-granularity HHMM logic), without altering the approved window.
