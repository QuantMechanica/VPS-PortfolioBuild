     the pre-existing `INFRA_FAIL` case;

     against the current repo bytes before the insert;

   - there is no open row, prior rerun of the same source, or already-terminal
     row bound to the current binary.

   reason, old and current EX5 hashes, current MQ5/setfile hashes,
   `historical_work_item_preserved=true`, and
   `rerun_source_current_ex5_mismatch_verified=true`.

2. **Exact-identity Q03.** `--ea ... --phase Q03` is now accepted only with one
   exact Q02/PASS predecessor and the expected current EX5 hash. The
   predecessor's payload must itself bind the current MQ5, EX5, setfile,
   symbol, period, and expert. Calling it without `--from-work-item-id` refuses
   broad fanout. If an old Q03 row exists, the caller must cite it through the
   append-only path; EA/symbol/setfile mismatches refuse.

3. **Later stale-gate hardening.** Append-only reruns of non-infrastructure
   terminal Q04–Q10 rows also require the current EX5 hash. The target must be
   terminal, unclaimed, and match the exact predecessor on EA, phase, symbol,
   and setfile. This preserves the previous infrastructure-rerun behavior while
   making stale evidence requalification hash-bound.

4. **Authenticated append-only contract phases.** New append-only
   Q09_NEWS/Q09_PORTFOLIO/Q10 rows now receive the same immutable dependency
   bindings as ordinary new rows. A Q09_PORTFOLIO row may be explicitly built
   from an exact Q08 `PASS` as well as the existing `FAIL_SOFT` path. This is
   necessary for a future Q10 to pair news and portfolio evidence from the same
