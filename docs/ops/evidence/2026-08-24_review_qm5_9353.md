## Confirmed defects

1. **Latent buffer overflow within the declared input range (correctness).**
   `ComputeStochRSIRaw()` allocates `double rsi_vals[14]` (mq5:58) then writes
   `rsi_vals[i]` for `i < strategy_stoch_period` (mq5:62-65). `strategy_stoch_period`
   is an input with SPEC range 7-30 (SPEC.md line 27); any value 15-30 indexes out
   of bounds → MQL5 array-out-of-range runtime halt. Defaults use 14 so Q02 with
   the shipped setfiles is safe, but the published optimization range is not. The
   array is also nearly dead: only `rsi_vals[0]` is read; min/max are tracked inline.
   Fix: drop the array (capture current RSI at i==0) or size/validate against the
   accepted period.

2. **OnTick suppresses required exits and the time stop (correctness, most material).**
   `Strategy_NoTradeFilter()` returns at mq5:297 — before `Strategy_ManageOpenPosition()`
   (mq5:300, 25-bar time stop) and `Strategy_ExitSignal()` (mq5:302, opposite-cross
   exit). The filter is entry eligibility (warmup, quote validity, spread > 0.15·ATR).
   A wide spread or invalid quote therefore blocks card-mandated exits on positions
   already open. Fix: keep Friday close, position management, and card exits reachable
   independently of new-entry eligibility; apply the spread gate to entry construction
   only.

3. **News blackout is half the approved window (card fidelity).**
   Card requires HIGH-impact blackout ±60 min of bar open (docs/strategy_card.md
   "News filter (P1 baseline)"). EA defaults `QM_NEWS_TEMPORAL_PRE30_POST30` (mq5:24)
   and passes literal `30, 30` to init (mq5:271). Framework exposes
   `QM_NEWS_TEMPORAL_PRE60_POST60`, so the representation exists. Fix: encode 60/60
   consistently in temporal mode, init call, SPEC, and regenerated setfiles.

4. **Malformed setfiles — not governed-generator output (hygiene/provenance).**
   All 13 setfiles contain 36 `0D 0D 0A` (CR CR LF) sequences each
   (e.g. `sets/..._EURUSD.DWX_H4_backtest.set`). A clean sibling produced by the
   governed generator (`framework/EAs/QM5_11299_.../sets/..._EURUSD.DWX_M5_backtest.set`)
   has 0 CRCRLF. Visible risk values are correct (`RISK_FIXED=1000`, `RISK_PERCENT=0`)
   but the records are not byte-stable. Fix: regenerate via `gen_setfile.ps1` and
   refresh build identity.
