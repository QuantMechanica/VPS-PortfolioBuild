## Verdict findings

### 1. Framework calendar corset is still violated

The current EA calls raw `CopyTime` and raw `iTime` for its entry-driving
calendar state (`QM5_12922_ariel-first-half-month-idx.mq5:69,78`) with no
`// perf-allowed` annotation. The formal review contract requires seasonal
calendar cadence to use `QM_IsNewCalendarPeriod`, `QM_CalendarPeriodKey`, or the
allowed higher-timeframe `QM_IsNewBar`; a raw `iTime` day/month key remains a
hard FAIL (`tools/strategy_farm/prompts/codex_review_ea.md:45-53`). This also
fails this ticket's explicit "no raw series without perf-allowed annotation"
criterion.

Named fix: replace the raw calendar boundary/key with the framework calendar
helpers. Put any bounded trading-session reconstruction behind a governed QM
helper, or add a narrowly justified `// perf-allowed` annotation for the bounded
history read and obtain reviewer sign-off.

### 2. Enabled Friday close changes the approved nine-session mechanism

The card requires one position to remain open through trading day T+9, normally
about 13 calendar days, and to close at T+9 session end (card:72-80). The EA
defaults `qm_friday_close_enabled=true` (`mq5:30`) and calls
`QM_FrameworkHandleFridayClose()` before strategy management (`mq5:242-243`).
That normally closes the monthly position on its first Friday, after which the
EA has no card-authorized re-entry path beyond T+2. The implemented exposure is
therefore not the approved T+1-through-T+9 exposure.

Named fix: declare the multi-session/weekend execution contract and disable the
framework Friday flatten for this baseline, or obtain a card amendment that
explicitly changes the strategy. Do not silently substitute the V5 default for
the approved holding rule.

### 3. The T+1 event-day rule is not actually wired

The card says to defer entry by one session when FOMC, NFP, or ECB falls on T+1
(card:91-92). The EA checks `QM_NewsAllowsTrade2` only at the entry tick
(`mq5:270-284`) using the generic PRE30/POST30 temporal profile. It does not
test whether one of the three named events occurs anywhere in the T+1 session;
an event later than the 30-minute pre-window will not defer the opening trade,
while an unrelated high-impact event can defer it.

Named fix: implement the card's named-event, whole-T+1-session predicate, then
defer exactly one trading session and fail closed when the calendar cannot prove
the result.

### 4. The recycle's restart-idempotency defect is only partially repaired

`Strategy_GetTradingDayOfMonth` now reconstructs the current D1 ordinal, but
`g_strategy_last_traded_month_key` and `g_strategy_entry_deferred` remain
process-local zero/false globals (`mq5:45-46`). `already_traded_this_month`
therefore resets after every restart (`mq5:108-116`). A restart during T+1 after
an already-attempted/closed trade can manufacture another T+1 opportunity, and
a restart after a news block loses the T+2 deferral. The prior recycle required
restart-safe behavior, not only an ordinal reconstruction.

Named fix: reconstruct the current-month trade/attempt state from durable deal
or framework evidence and reconstruct the event-day deferral, with a fail-closed
fallback when either state cannot be proved.
