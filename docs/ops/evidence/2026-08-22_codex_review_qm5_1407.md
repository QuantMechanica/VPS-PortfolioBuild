## Blocking findings

1. **The required pending-order OCO entry is absent.** The approved card requires simultaneous ATR-buffered BUY-STOP and SELL-STOP orders, first-fill cancellation of the opposite order, a 12-H4-bar lifetime, and per-bar cancellation when the apex has passed (card lines 79-86). `Strategy_EntrySignal` instead waits for a closed-bar breakout and returns a market `QM_BUY` or `QM_SELL` request with `req.price=0` and `req.expiration_seconds=0` (MQ5 lines 406-488). There is no bracket lifecycle, OCO cancellation, or 12-bar expiry.

2. **The spread rule was replaced by a different mechanic.** The card requires `spread <= 0.25 * ATR(14,H4)` (line 112). `Strategy_SpreadAllowsEntry` permits spread up to 1.5 times a rolling average spread (MQ5 lines 147-170). Updating `SPEC.md` to describe the implementation does not authorize changing the approved strategy.

3. **The registered/setfile universe does not match the card.** The approved symbols are EURUSD, GBPUSD, XAUUSD, NDX, WS30, GDAXI, UK100, and XTIUSD (card lines 21-22 and 43-44). The build adds AUDUSD, NZDUSD, SP500, USDCAD, USDCHF, and USDJPY, and omits XTIUSD. The added symbols are not named by card R3.

4. **Past-apex patterns are not rejected.** The card says current-bar-at-or-beyond-apex invalidates the pattern (lines 84-86). The implementation only enforces a maximum future extension (`apex_shift < 1 - extension`) and has no corresponding rejection for an apex already behind the current bar (MQ5 lines 355-362).

5. **The pattern-reuse guard is incomplete.** The card requires a 20-H4-bar guard after entry *or invalidation* and identifies reuse by more than 50% shared pivots (lines 114-116). The implementation only searches entry deals from the last 60 days and blocks any same-magic entry within 20 bars (MQ5 lines 117-145); it records neither invalidations nor pivot-set overlap.

6. **Open-position management is not restart-safe.** TP1 price/status and the trendline projection state are RAM-only globals. After an EA/terminal restart with an open position, the partial close and pattern-failure exit lose the state they require. The position is then left only with broker SL/TP and the time stop. This violates safe recovery for an actively managed position.

7. **TP1 is marked complete even when its actions fail.** The implementation ignores the return values from partial close and stop movement, then unconditionally sets `g_tp1_done=true` (MQ5 lines 518-525). An invalid normalized partial size or trade-operation failure permanently suppresses retries.

8. **The pattern-failure projection does not advance with time.** `Strategy_ExitSignal` uses the constant `x_now = g_last_ref_shift - 1` on every later H4 bar (MQ5 lines 543-559). It therefore tests the close against a frozen line value rather than the card's line projected to the current bar (card lines 94-96).
