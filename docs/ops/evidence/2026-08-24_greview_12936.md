### 3. Dead strategy input — pullback-depth cap cannot affect valid signals

All 12 `strategy_*` inputs have textual use-sites, but one is semantically dead for the approved positive sweep domain:

- Buy rule 5 requires `bar1.low > bar2.low` at `.mq5:101-102`; the later cap admits when `bar1.low >= bar2.low - strategy_max_pullback_atr_mult * atr` at `.mq5:167-173`.
- Sell rule 5 requires `bar1.high < bar2.high` at `.mq5:117-118`; the later cap admits when `bar1.high <= bar2.high + strategy_max_pullback_atr_mult * atr` at `.mq5:193-199`.
- ATR must be positive at `.mq5:142-143`, and the card permits only positive cap values `{1.0, 1.5, 2.0, 2.5}` at the approved card's lines 82-83.

Therefore each cap condition is already true whenever the corresponding five-rule signal is true. Changing `strategy_max_pullback_atr_mult` within its declared domain cannot change entry admission, which violates the review rule that a dead declared strategy input is a rejection defect. It also fails the card's stated `bar[0]` versus `bar[2]` maximum-depth mechanism (`card:82`) by comparing the same adjacent bars already constrained by rule 5.

Named fix: implement the card's distinct bar-reference depth comparison (with the signal/bar-shift mapping made explicit) and add a focused unit/static fixture proving that at least two approved cap values produce different admission outcomes on a boundary example.

### 4. Additional framework/mechanism defects

- `QM_IsNewBar` is stateful: `framework/include/QM/QM_Indicators.mqh:140-165` shows the first call advances `last_bar_time` and a second same-key call returns false. With an open position, the EA consumes the edge in `Strategy_ExitSignal` at `.mq5:294-321`, then tests it again before entry at `.mq5:375`. An opposite signal may close the position but deterministic same-bar reversal entry is suppressed. Fix by computing the edge once and sharing it across exit and entry decisions.
- The MAE hook exists, but `QM_KillSwitchCheck()` returns first at `.mq5:344-347`. This can skip required open-position MAE sampling while the kill switch is active. Move `QM_FrameworkTrackOpenPositionMae()` ahead of every per-tick early return, preserving the V5 skeleton order.
- The card specifies an eight-H4-**bar** time stop (`card:61-65`), while `.mq5:303-307` uses wall-clock seconds; weekends and market closures age the timer without producing bars. Use the framework's completed-bar hold calculation or an equivalent restart-safe bar count.
- Cooldown timestamps are written when a signal request is formed (`.mq5:173-185`, `.mq5:199-211`) before `QM_TM_OpenPosition` is attempted at `.mq5:378-383`; a rejected order burns the four-bar cooldown. Stamp successful-entry state only after the transaction manager reports success.

These are actionable build defects, not changes to a gate threshold or criterion.
