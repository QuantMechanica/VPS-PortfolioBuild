# rb-sh2-sh3 — Farm-DB schema hardening evidence

Date: 2026-08-23

Branch: `rb-sh2-sh3`

Activation status: **prepared and copy-tested; not applied to the live farm DB**

## 1. Scope and safety

This ticket implements SH-2 per-run artifact identity and the SH-3 successor for typed,
constrained verdict storage. No factory state, queue, gate criterion, threshold, live terminal,
or live verdict row was changed. The production database was used only as the read-only source
of a SQLite-backup-API copy at
`scratch/rb-sh2-sh3-db-copy/farm_state.sqlite`; every write and migration test targeted that
copy.

## 5. Factory_OFF activation commands

Run from the deployed worktree while the orchestrator has independently established Factory_OFF.
The backup destination below must not already exist.

```powershell
python tools/strategy_farm/schema_hardening.py migrate-sh2 --dry-run --db D:/QM/strategy_farm/state/farm_state.sqlite
python tools/strategy_farm/schema_hardening.py migrate-sh3 --dry-run --db D:/QM/strategy_farm/state/farm_state.sqlite
python tools/strategy_farm/schema_hardening.py migrate-sh2 --apply --db D:/QM/strategy_farm/state/farm_state.sqlite
python tools/strategy_farm/schema_hardening.py migrate-sh3 --apply --db D:/QM/strategy_farm/state/farm_state.sqlite --backup D:/QM/strategy_farm/state/backups/farm_state_20260823_factory_off_pre_rb_sh3.sqlite
python tools/strategy_farm/schema_hardening.py --validate-sh3 --db D:/QM/strategy_farm/state/farm_state.sqlite
```

Dry-runs and validation open the DB with SQLite URI `mode=ro`. Apply is deliberately explicit;
SH-3 refuses to run without a backup path and refuses to overwrite an existing backup. SH-3 also
runs the SH-2 ensure function idempotently, so a retry after SH-2 success is safe.
