## Deterministic blocker

The approved card evaluates the signal at completed bar `[1]` and defines the
20-bar extreme over `i=1..20` (`strategy-seeds/cards/approved/QM5_33006_andrea-unger-turtle-soup-false-breakout.md:74-76`).
It then requires:

- long: `Low[1] < Low20` (`...md:89-90`), and
- short: `High[1] > High20` (`...md:92-93`).

Those predicates are unreachable under the card's own definition:

```text
Low20  = min(Low[1], ..., Low[20])   => Low20 <= Low[1]
High20 = max(High[1], ..., High[20]) => High20 >= High[1]
```

Therefore `Low[1] < Low20` and `High[1] > High20` are both always false. The
existing EA silently changes the window to bars `[2..21]` through `iHighest` /
`iLowest(..., start=2)`
(`framework/EAs/QM5_33006_andrea-unger-turtle-soup-false-breakout/QM5_33006_andrea-unger-turtle-soup-false-breakout.mq5:146-155`),
which is an economic strategy rewrite, not an implementation of the approved
formula.

The entry execution contract is also internally inconsistent. The exact rules
say `BUY_STOP` / `SELL_STOP` at the prior extreme plus/minus one tick
(`...md:89-93`), while the card's deterministic MQL5 example emits market
`ORDER_TYPE_BUY` / `ORDER_TYPE_SELL` (`...md:186-201`). The card provides no
rule for an already-crossed stop price, pending-order lifetime, or a bar that
satisfies both directional conditions. Choosing skip, market-if-crossed,
expiry, or precedence would change entry frequency and alpha without OWNER
approval.
