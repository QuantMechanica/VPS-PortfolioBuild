## Findings requiring recycle

### 1. Default risk inputs fail framework initialization

The EA simultaneously defaults `RISK_PERCENT=0.5` and `RISK_FIXED=1000.0` at
`framework/EAs/QM5_39006_forexfactory-spudfyre-stochastic-ribbon/QM5_39006_forexfactory-spudfyre-stochastic-ribbon.mq5:28-29`.
`QM_FrameworkValidateRiskInputs` explicitly rejects both-positive inputs at
`framework/include/QM/QM_Common.mqh:166-176`. The delivered Q02 setfiles do
override this to fixed risk, but the source default itself cannot initialize
and does not provide a clean backtest/live mode contract.

**Named fix:** make the EA defaults mutually exclusive (`RISK_PERCENT=0`,
`RISK_FIXED=1000` for the governed backtest build), retain the existing Q02
setfile values, and require any future governed live preset to set
`RISK_FIXED=0` plus its approved positive `RISK_PERCENT`.

### 2. The GMT rollover blackout is evaluated in broker time

The approved card declares `23:55-00:05 GMT` at card line 86. The EA instead
passes raw `TimeCurrent()` into `TimeToStruct` at source lines 127-130. The
read-only hardening check reproduces this as:

```text
EA_BROKER_TIME_USED_FOR_GMT_WINDOW: ... has a card-declared GMT/UTC clock
window but compares raw TimeCurrent/iTime hours without QM_BrokerToUTC or a
documented equivalent.
```

**Named fix:** convert the broker clock with `QM_BrokerToUTC(TimeCurrent())`
before applying the 23:55-00:05 minute window, then cover the conversion in a
focused static/unit regression.

### 3. The card's three-tick slippage cap is not wired

The approved card caps market-order slippage at 3.0 ticks at card line 114.
The EA has no slippage input or `QM_EntryConfigure` call. Consequently the
framework keeps `g_qm_entry_deviation_points=20` from
`framework/include/QM/QM_Entry.mqh:63-88`, and places that value into every
market request at `framework/include/QM/QM_Entry.mqh:452-462`.

**Named fix:** add a bounded three-tick strategy input, validate it fail-closed,
convert symbol ticks to MT5 deviation points using `SYMBOL_TRADE_TICK_SIZE /
SYMBOL_POINT`, pass the result through `QM_EntryConfigure`, and regenerate all
three governed setfiles.

### 4. Approved `InpStochPeriods` is absent from the EA

The approved MQL5 parameter table declares `InpStochPeriods` at card line 163.
The EA's complete strategy-input declaration block at source lines 46-57 does
not expose it; the periods are hardcoded as `{6,9,12,14,18,24,30}` at source
line 72 and consumed at lines 76-85. A grep of every source-declared input
found 25/25 with at least one executable use-site, so there is no dead input
among the declarations that exist; this is instead a missing card-declared
input.

**Named fix:** implement and validate the approved `InpStochPeriods` parameter
and use its parsed seven periods for the ribbon and fast/anchor reads (or obtain
OWNER authorization to change the approved card contract); then regenerate
setfiles and focused tests.

These defects are mechanical and salvageable, so `RECYCLE` is appropriate;
they do not justify `FAILED`.
