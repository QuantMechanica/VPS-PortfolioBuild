## Actionable RECYCLE findings

1. **The implemented CUSUM recurrence is not the approved recurrence.** The
   card requires `y_t - E[y_t]` in both accumulators
   (`D:/QM/strategy_farm/artifacts/cards_approved/QM5_37006_cusum-filter-structural-breakout.md:76`).
   The EA calculates the rolling mean while deriving variance
   (`framework/EAs/QM5_37006_cusum-filter-structural-breakout/QM5_37006_cusum-filter-structural-breakout.mq5:76-92`)
   but adds the raw close difference to the accumulators at `:103-105`.
   **Named fix:** return the rolling mean with the standard deviation and
   accumulate `diff - mean`; if the card does not define the estimator tightly
   enough, obtain an approved card clarification instead of inventing one.

2. **A rejected entry consumes the path-dependent signal.** The card resets
   CUSUM only upon trade execution (approved card `:99`). The source clears both
   accumulators while merely constructing a request (`mq5:174-194`), then calls
   `QM_TM_OpenPosition` later and ignores its result (`mq5:297-303`).
   **Named fix:** reset only after the framework confirms a successful entry
   (or from a confirmed entry transaction); retain state on rejection.

3. **All three approved loss rails are absent.** The card requires a 2.0%
   daily realized-loss entry halt (`approved card:87`), 2.5% daily hard stop,
   and 5.0% total-drawdown stop (`approved card:112-113`). The EA exposes none
   and only calls the legacy framework initializer (`mq5:218-236`). That path
   configures a generic 3.0% daily equity halt and 0.0% portfolio-DD halt
   (`framework/include/QM/QM_Common.mqh:296-298`). The read-only hardening check
   reports three `EA_CARD_LOSS_LIMIT_MISMATCH` failures.
   **Named fix:** wire the exact card values into explicit, restart-safe entry
   and hard-stop enforcement; do not rely on the generic 3.0/0.0 defaults.

4. **CUSUM state is conditional on entry filters and is not restart-stable.**
   `OnTick` returns for the kill switch, Friday close, rollover/spread filter,
   and central news filter before its new-bar gate and state advance
   (`mq5:250-293`). Closed bars during any such block are omitted from the
   approved path-dependent recurrence. On restart, the RAM-only accumulators
   initialize to zero (`mq5:59-60`) and `OnInit` processes only one delta
   (`mq5:238`), adding an unauthorized reset.
   **Named fix:** advance/reconstruct exactly once for every completed M15 bar
   independently of entry-only filters, persist or deterministically replay
   bounded state on restart, and fail closed when reconstruction is incomplete.

5. **The EA adds an unapproved absolute spread filter.** The card authorizes
   only `spread > 1.8 * ATR(14,M15)[1]` (`approved card:85`). The additional
   `strategy_max_spread_points=300` input and rejection branch
   (`mq5:53,143-144`) change the authorized entry set.
   **Named fix:** remove this input/filter or obtain an OWNER-approved card
   variant that declares it.

6. **The three-tick slippage ceiling is not enforced.** The card caps market
   order slippage at three ticks (`approved card:114`), while the inherited
   entry configuration uses a generic 20-point deviation
   (`framework/include/QM/QM_Common.mqh:296-297`) and this EA supplies no
   tick-size conversion or override.
   **Named fix:** configure deviation from `SYMBOL_TRADE_TICK_SIZE` so it is no
   greater than three trade ticks on each registered symbol.

7. **Raw history reads lack the required performance/bounds annotation.** The
   two `CopyRates` calls are bounded and check their return counts
   (`mq5:68-92,95-115`), so no unbounded indicator-buffer defect was proven,
   but neither raw-series read carries a `perf-allowed` annotation or an
   explicit `ArraySize` guard.
   **Named fix:** add the governed bounded-read annotations and mechanically
   tied `ArraySize` proofs when implementing the recurrence/replay repair.

After these source fixes, **recompile via governed `COMPILE_EA`** and regenerate
the producer identity/setfile build bindings. Direct compilation was forbidden
