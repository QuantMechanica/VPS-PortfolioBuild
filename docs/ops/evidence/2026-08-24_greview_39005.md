## Actionable defects

1. **GMT rollover window uses broker time.** The approved card declares `23:55–00:05 GMT` (`card:84-86`), while `Strategy_NoTradeFilter` converts raw `TimeCurrent()` directly with `TimeToStruct` (`framework/EAs/QM5_39005_forexfactory-genesis-matrix-scalper/QM5_39005_forexfactory-genesis-matrix-scalper.mq5:242-246`). Fresh `build_gate_hardening.py` reports `EA_BROKER_TIME_USED_FOR_GMT_WINDOW`. Fix: convert broker time through the governed UTC helper (for example `QM_BrokerToUTC`) before calculating the minute-of-day.

2. **The source defaults select both mutually exclusive risk modes.** `RISK_PERCENT=0.5` and `RISK_FIXED=1000.0` are simultaneously positive (`mq5:33-36`). `QM_FrameworkValidateRiskInputs` rejects that combination (`framework/include/QM/QM_Common.mqh:166-177`), so a default attach fails `OnInit`. The two governed backtest setfiles correctly override this to `RISK_FIXED=1000` and `RISK_PERCENT=0` (`sets/*_backtest.set:17-21`), but the EA source contract is still invalid and does not itself provide a valid live-percent default. Fix: keep exactly one source risk mode active; governed backtest presets must remain fixed-risk, and any future live preset must use positive `RISK_PERCENT` with `RISK_FIXED=0`.

3. **The card's three-tick slippage cap is not wired.** The approved card sets a maximum of 3.0 ticks (`card:110-113`). The EA never reconfigures entry deviation after `QM_FrameworkInit`; the framework therefore installs its 20-point default (`framework/include/QM/QM_Common.mqh:296-297`, `framework/include/QM/QM_Entry.mqh:63-88`) and sends it on market requests (`QM_Entry.mqh:452-463`). Fix: convert three symbol ticks to the framework's deviation-point unit and configure that value through `QM_EntryConfigure`, preserving the existing news, stress, and host-magic bindings.

4. **The dynamic T3-CCI buffer has no explicit `ArraySize` guard.** `cci_buf` is dynamically resized and then indexed at `[0]` and `[i]` (`mq5:119-125`, `mq5:130`, `mq5:140-148`), with no `ArraySize(cci_buf)` proof anywhere in the EA. This violates the ticket's explicit bounded-buffer/`ArraySize` review contract even though the current general-purpose D10 analyzer accepts a resize-count proof. Fix: check the resize result/`ArraySize` before the first index and bind subsequent loop bounds to the proved size.
