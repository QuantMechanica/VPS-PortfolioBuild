# Slice i1_ftmo_first_passage — report

Directive 3 §34 (FTMO first-passage / breach model) and §43 item I. OWNER-DEC-CBE-20260915.

## What was built

A deterministic, seeded **block-bootstrap first-passage / breach model** for the
representative intended FTMO Demo portfolio, plus wiring into the existing FTMO
fitness and challenge-readiness surfaces. It answers §34 in full and is not reduced
to a single score.

New engine `tools/strategy_farm/ftmo/first_passage.py`
(schema `qm.ftmo-first-passage/v1`, read-model `D:/QM/reports/state/ftmo_first_passage.json`):

- Resolves the intended Demo roster three ways (never guessing a symbol):
  - `roster_from_recompose_manifest` — from a sealed `qm.recompose-frozen-inputs/v1`
    snapshot (the `demo_8` incumbent already carries the FTMO→DWX mapping, e.g.
    `USOIL.cash`→`XTIUSD.DWX`, and sha-pinned frozen streams; sha256 is verified
    against the manifest, mismatch drops the sleeve).
  - `roster_from_demo_cycle` — from the live `ftmo_demo_cycle.json` ledger with a
    documented FTMO→DWX resolver (`resolve_dwx_symbol`, sourced from
    `venue_cost_model.json` aliases); an unresolved stream drops the sleeve with an
    explicit `EVIDENCE_MISSING` note.
  - `roster_from_spec` — explicit candidate rosters passed in.
- Streams → per-Prague-day book: RISK_FIXED $1000/100k = 1.0 %/trade convention
  (shared with `recompose/metrics.py`, `ftmo_p1_mc.py`); each sleeve scaled by its
  `risk_pct`. Intraday drawdown is modelled via a conservative per-trade-MAE
  intraday-low proxy (`mae_acct`) rather than ignored.
- Calendar-aligned block bootstrap over the all-active intersection window (cross-
  sleeve co-movement preserved inside each real day; block length preserves short-
  horizon autocorrelation). Vectorised NumPy first-passage walk.
- Official parameters read **only from the bound rulepack**
  (`FTMO_2S_100K_STANDARD_V2.json` via `ftmo_rule_contract`): +10 % target on
  end-of-day balance, −5 % daily-loss and −10 % static total-loss on intraday
  equity, ≥4 opening days, **no time limit**. Breaches tested before target
  (conservative); unresolved paths reported as **censored**, never hidden.
- Outputs: P(target hit), P(daily-loss breach), P(max-loss breach), P(censored),
  P(target hit | resolved), time-to-target p10/p50/p90/mean, bounded-horizon pass
  marks (30/60/90/180/252 calendar days mapped to business days 5/7), cost/slippage
  sensitivity grid (same bootstrap indices reused → apples-to-apples), and
  **conditional failure modes** (dominant breach sleeve, symbol, and weekday, split
  daily vs total). Reproducible from a frozen input manifest
  (`qm.ftmo-first-passage-manifest/v1`, per-stream sha256 + seed + params).

## Method notes / limitations (honestly labelled)

- Backtest-derived, gross-of-slippage. Intraday equity is a per-trade-MAE proxy, not
  tick-exact mark-to-market → a conservative approximation, not a rule-exact MTM
  (matches the `ftmo_complete_mtm_evidence` go-criterion which remains OPEN).
- Book intraday low sums all sleeves' troughs on a day (conservative overstatement of
  drawdown → never understates breach probability).
- Bounded-horizon marks map calendar→business days via 5/7; FTMO has no maximum
  trading period, so the headline is the no-deadline first passage with censoring
  reported.
