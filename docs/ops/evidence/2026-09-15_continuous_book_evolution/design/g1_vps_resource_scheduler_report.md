## NOT done (with reasons)

- **CPU share / disk I/O footprint** — the per-run ledger
  (`qm.tester_memory_ledger/v1`) records neither counter, so they are reported as
  `NOT_EVALUATED / EVIDENCE_MISSING` rather than guessed (engineering rule:
  explicit UNKNOWN). Per-run RSS sampling the slice asked to add "if none" was
  already present in the worker monitor loop (`_sample_tester_memory` →
  `peak_subtree_working_set_gb`), so no sampling code was added; adding CPU/disk
  counters to the ledger is a separate worker change (out of this slice's blast
  radius). Recommended follow-up ticket if CPU/disk scheduling is wanted.
- **Family-dimension footprint** — the ledger carries `ea_id` but not family; the
  read-model accepts an optional `--family-map` and otherwise reports family as
  EVIDENCE_MISSING. No canonical ea_id→family map was wired (would couple to the
  lineage/universe read-models); left as an opt-in argument.
- **Redirecting the atomic claim to a specific fitting row** — the seam suppresses
  the fleet-parking pre-drain so the existing claim loop naturally claims fitting
  rows; it does not rewrite `farmctl.claim_atomic` to force a specific id (that
  would touch the atomic-claim invariants the slice said to leave untouched).
- **Not committed / no task registered / no worker reload** — per RED boundaries
  the orchestrator commits, registers tasks, and reloads workers; exact commands
  below.
