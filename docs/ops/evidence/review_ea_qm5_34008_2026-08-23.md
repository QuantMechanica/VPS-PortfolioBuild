## Findings

**Inputs — all wired.** `strategy_lookback_hours`, `strategy_dispersion_dev`,
`strategy_atr_period`, `strategy_spread_atr_mult` (entry path); `strategy_target_profit_pct`,
`strategy_hard_stop_loss_pct` (exit path). No unwired-input defect (the QM5_1355 class).

**Magic/slot registry — consistent.** `magic_numbers.csv` rows for 34008: 7 slots (0–6) map
1:1 onto `g_basket_symbols` array order (EURUSD…USDJPY), magic = `340080000 + slot`.
`req_a.symbol_slot = min_idx`, `req_b.symbol_slot = max_idx` index into the same array — no
host/slot/magic conflation (the class from `project_qm_host_slot_magic_conflation_2026-08-16`).

**Risk/news — compliant.** `RISK_FIXED=1000`, `RISK_PERCENT=0` (correct for Q02–Q10 backtest per
Hard Rules). `qm_news_stale_max_hours=336` — at, not above, the ceiling.

**Package semantics.** Entry opens two offsetting legs (long the most-USD-lagging pair, short the
most-USD-leading pair by dispersion from the basket mean, each direction adjusted for
`IsDirectUSDPair`) at half `QM_LotsForRisk` each, so the package's aggregate risk ≈ one unit of
`RISK_FIXED` if both legs have similar SL distance. Package exit is basket-level: closes both legs
on combined %-of-balance TP/SL, or if one leg becomes an orphan (`OpenPackageCount()==1`,
`Strategy_ManageOpenPosition`). This is a legitimate market-neutral (USD-exposure-neutral, not
strictly currency-neutral) basket-dispersion design — Gemini's claim holds up on inspection.

**Defect (doc-only, non-blocking): `SPEC.md` §2 parameter table is stale.** It lists
`strategy_tp_rr_mult`, which does not exist anywhere in the `.mq5`, and omits the two inputs that
actually gate the exit (`strategy_target_profit_pct`, `strategy_hard_stop_loss_pct`). The SPEC is
marked "auto-generated ex-post by gen_spec_md.py, 2026-08-17" — it was generated from a different
parameter set than what actually shipped, or the strategy was edited post-generation without a
regen. Does not block Q02 backtest (the setfiles were generated from the actual `.mq5` inputs, not
from SPEC.md), but the spec is currently wrong about its own EA and should be regenerated.

**Observation, not a defect:** the `QM_EntryRequest req` populated at the top of
`Strategy_EntrySignal` (lines 148–154) is never read — the function always exits through the
direct `QM_BasketOpenPosition` path and returns `false`, and `OnTick` (line 368) discards both the
return value and `req`. Confirmed this matches the sibling basket EA's convention, so it is
boilerplate carried across the basket-EA template, not a 34008-specific mistake.
