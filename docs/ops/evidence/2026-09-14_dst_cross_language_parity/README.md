## What was built

1. **`tools/strategy_farm/dst_rule_golden_table.py`** — an independent, from-scratch
   re-implementation of `qm.dst_rule.us.v1` (2nd Sunday of March 07:00 UTC start, 1st
   Sunday of November 06:00 UTC end, UTC+3/UTC+2), written without importing or copying
   `news_impact_mapping.py`'s `_nth_weekday_of_month` (different algorithm: forward
   day-walking vs `calendar.weekday`/`calendar.monthrange`). Generates a dense per-minute
   sweep (±3h around both boundaries) for 2023–2027 — spans leap year 2024 and four
   non-leap years, satisfying the "at least 3 consecutive years spanning a leap and a
   non-leap year" requirement. Output:
   `docs/ops/evidence/2026-09-14_dst_cross_language_parity/golden_table.csv` (3,610 rows,
   no duplicate timestamps).

2. **`tools/strategy_farm/tests/test_dst_rule_cross_language_parity.py`** (new, 8 tests,
   10 subtests) — validates `news_impact_mapping.py`'s ported DST rule against every one
   of the 3,610 golden rows (`is_us_dst`, `broker_offset_hours`, `utc_to_broker`), plus
   explicit boundary (±1 minute, no off-by-one) and November-fallback-ambiguity checks for
   all 5 years. **All green**, 0 mismatches across all 3,610 rows.

3. **`framework/tests/unit/dst_aware_transition_tests.mq5`** (extended) — the pre-existing
   MQL5 unit test (previously 2026-only) now loops over the same 5 years, computing each
   year's DST boundary **dynamically** via `QM_DSTAware_USDSTStartUTC`/`EndUTC` (the
   production nth-weekday-at-test-time code — no hardcoded literals for the rule itself),
   and cross-checks the dynamically computed boundary against `GOLDEN_START_UTC`/
   `GOLDEN_END_UTC` — instants generated by (1), documented as generated, not hand-picked.
   Adds a dense ±180-minute per-minute sweep around every boundary in every year (mirrors
   the Python-side density) and the November-fallback check per year. **Not compiled or
   executed in this cycle** — MQL5 compilation/execution belongs to the factory build
   pipeline (Codex-owned per the agent routing contract; the one available headless
   MetaEditor probe, `tools/strategy_farm/monitor_compile_probe.py`, is scoped to a
   different task's isolated portable environment and contract, not a general-purpose
   compiler). Manual review: every function/field used
   (`QM_DSTAware_USDSTStartUTC/EndUTC`, `QM_IsUSDSTUTC`, `QM_BrokerUtcOffsetHoursForUTC`,
   `QM_BrokerToUTC`, `TimeToStruct`, `.day_of_week`, `StringFormat`, array-with-initializer
   syntax) is already used correctly elsewhere in this codebase (grep-verified against
   `framework/include/QM/*.mqh` and existing EAs); the file follows the pre-existing test's
   exact structure and style. This is evidence of care, not a substitute for an actual
   compile — flagged honestly as such.

4. **`docs/ops/evidence/2026-09-14_dst_cross_language_parity/regression_f03.py`** +
   `regression_f03_report.json` — reproduces the F-03 finding directly from
   `D:/QM/data/news_calendar/forex_factory_calendar_clean.csv` (48,727 rows, both
   `DateTime_UTC` and `DateTime_EET` present). For every row, computes the *legacy*
   failure mode (treating `DateTime_EET`'s offset from UTC as if it were broker time —
   EET follows EU DST, Darwinex broker time follows US DST, and the two disagree in the
