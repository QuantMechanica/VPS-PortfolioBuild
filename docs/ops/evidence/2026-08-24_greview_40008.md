## Actionable defects

### 1. The card's 3-tick slippage limit is not implemented

The approved card requires `Max 3.0 ticks on market orders`
(`D:/QM/strategy_farm/artifacts/cards_approved/QM5_40008_aqr-value-and-momentum-everywhere.md:110-113`).
The EA declares no slippage/deviation input (`.mq5:26-66`) and calls
`QM_FrameworkInit` without any strategy-specific deviation (`.mq5:338-353`). The
framework consequently calls `QM_EntryConfigure(..., 20, ...)`
(`framework/include/QM/QM_Common.mqh:296-297`), and that value is applied to
`MqlTradeRequest.deviation` (`framework/include/QM/QM_Entry.mqh:462`).

Named fix: expose the approved 3-tick cap through the framework-approved entry
configuration path, converting ticks to deviation points using the symbol's tick
size/point relationship. Do not retain the silent 20-point default.

### 2. The four-asset engine never opts into the V5 basket symbol guard or warmup

The EA declares a four-symbol cross-sectional universe at `.mq5:69-72` and reads
all members at `.mq5:161-181`, but `OnInit` never calls
`QM_SymbolGuardInit(g_universe)` or `QM_BasketWarmupHistory(...)` after
`QM_FrameworkInit` (`.mq5:333-364`). `QM_FrameworkInit` resets every EA to the
single-symbol guard (`framework/include/QM/QM_Common.mqh:241-246`), while the
framework contract says basket/portfolio EAs must opt in after init and should
ship a basket manifest (`framework/include/QM/QM_SymbolGuard.mqh:11-16`). The EA
directory contains no `basket_manifest.json`. The framework's own history-warmup
contract explains that `SymbolSelect` alone is insufficient in the tester and
provides the governed `CopyClose` warmup path
(`framework/include/QM/QM_SymbolGuard.mqh:100-140`).

Named fix: after successful `QM_FrameworkInit`, initialize the explicit four-symbol
guard, warm all four D1 histories to at least `InpValDays + 2`, and add the governed
basket manifest before evaluating cross-symbol factors.

### 3. Missing universe members silently change the strategy

The card defines a cross-sectional rank over the declared universe
(`D:/QM/strategy_farm/artifacts/cards_approved/QM5_40008_aqr-value-and-momentum-everywhere.md:72-77`),
and `SPEC.md:13-17` makes the universe explicitly four assets. The implementation,
however, proceeds whenever only two members are valid (`.mq5:195-203`) and then
normalizes ranks by that reduced `valid_count` (`.mq5:205-221`). This changes the
rank grid and the fixed 0.70/0.30 entry semantics whenever one or two histories or
long-lookback indicators are missing.

Named fix: fail closed unless every declared universe member is valid
(`valid_count == UNIVERSE_SIZE`), with setup-data evidence identifying missing
members; do not rank a silently reduced universe.

### 4. Quarterly cadence bypasses the tester-robust framework calendar helper

The card requires quarterly factor rebalancing
(`D:/QM/strategy_farm/artifacts/cards_approved/QM5_40008_aqr-value-and-momentum-everywhere.md:96-98`).
The EA hand-rolls a file-scope broker-time quarter/year latch at `.mq5:81-82` and
`.mq5:129-147`, invoked on every tick at `.mq5:319-321`. V5 already supplies a
D1-derived, tester-robust calendar key and latch, explicitly avoiding MN1/W1
custom-symbol gaps and reload edge problems
(`framework/include/QM/QM_Indicators.mqh:203-215,217-275`).

Named fix: derive the quarter from `QM_CalendarPeriodKey(PERIOD_MN1)` (or add/use a
governed quarterly helper based on it), retain one-shot semantics, and remove the
raw broker-time quarter latch.

### 5. Delivered binary is stale relative to the remediated source

The source was materially changed in commit `5ec0bbf8f` on 2026-08-23; that commit
changed only the `.mq5` (233 insertions, 183 deletions) and did not update the
`.ex5`. `git log -- <ex5>` shows the binary's last commits as `79b2a2af2` and
`139ece403`, both on 2026-08-18. Thus the delivered binary predates the current
cross-asset-rank/loss-limit source revision.

The build-result hashes are:

- normalized LF source SHA-256: `0d91c717347a8a7ee537ac0850b7fa91cbb1b090983d8fea47b3955ee6f131d7`
  (`artifacts/qm5_40008_build_result.json:6-7`);
- delivered EX5 SHA-256: `1e1cbe5582c9f2b3cf523e0c9350ca44cd5762dbf87424797326c5f63db2b66f`
  (`artifacts/qm5_40008_build_result.json:8-9`).

The worktree source is the same Git blob as the canonical compiled-source path;
its raw SHA differs only because this checkout materializes CRLF. Normalizing its
CRLF to LF reproduces the recorded source hash exactly. That removes an EOL false
positive but does not cure the binary lineage failure: the tracked `.ex5` itself
was not rebuilt when the source changed.

Named fix: after defects 1-4 are corrected, **recompile via governed `COMPILE_EA`**
and retain a compile/build-identity artifact that binds the new source hash to the
fresh EX5 hash. Do not reuse the current binary.
