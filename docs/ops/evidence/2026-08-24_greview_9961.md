## Blocking findings

### 1. Per-tick full-window Supertrend rebuild

- `Strategy_GetSupertrendStates` requests `warmup + 2` raw D1 rates and walks the returned
  history (`QM5_9961...mq5:83-142`, specifically `CopyRates` at line 94, the history loop
  at line 104, and a pooled ATR call inside that loop at line 111).
- `Strategy_ExitSignal` calls that rebuild at line 279.
- `OnTick` calls `Strategy_ExitSignal` at line 371, while its only `QM_IsNewBar()` gate is
  later at line 393. Therefore the full closed-bar history is rebuilt on every incoming
  tick even though all signal values are based on closed D1 bars.

This violates the binding runtime-performance rule in
`tools/strategy_farm/prompts/claude_review_ea.md` section 7. Required repair: evaluate the
exit path behind one shared `QM_IsNewBar()` result (without consuming the framework edge
twice), while retaining per-tick safety management that genuinely needs per-tick cadence.

### 2. The 60-trading-day time stop is implemented as 60 calendar days

The approved card requires `60 trading days from entry` (card line 62). The EA instead
tests `TimeCurrent() - opened >= strategy_max_hold_bars * PeriodSeconds(D1)`
(`QM5_9961...mq5:272-295`). Weekend/non-trading time therefore advances the stop and exits
materially earlier than 60 completed D1 trading bars. Required repair: count completed D1
bars since `POSITION_TIME` (or use an equivalent framework bar-count helper), not elapsed
wall-clock seconds.

### 3. Raw-series path is not annotated or explicitly bounded/guarded

The Supertrend reader declares a dynamic `MqlRates rates[]` and calls raw `CopyRates`
(`QM5_9961...mq5:92-95`) with no `perf-allowed` annotation. Its requested size comes from
the externally configurable `strategy_warmup_bars`; validation supplies only a lower bound
(`QM5_9961...mq5:70-80`) and no finite upper bound. Although the loop is tied to the
`CopyRates` return count and the automated D10 check therefore reports zero failures, the
delivered code contains no explicit `ArraySize(rates)` guard before indexed access. This
does not satisfy the ticket's stricter raw-series/buffer contract. Required repair: cap the
history request at a finite card-sufficient depth, add the approved performance annotation,
and fail closed unless both the copied count and `ArraySize(rates)` prove every indexed
element exists.
