## Blocking findings

### 1. The implemented mechanism is not the approved spread-package mechanism

The card specifies OU calibration on cointegrated currency-pair spreads and
explicitly orders `BUY Spread Package` / `SELL Spread Package`
(`cards_approved/...md:61,91-94`). The EA instead reads only `_Symbol` closes,
fits OU directly to that one price series, and emits one `_Symbol` market order:

- `framework/EAs/QM5_37001_ernest-chan-ornstein-uhlenbeck-statarb/QM5_37001_ernest-chan-ornstein-uhlenbeck-statarb.mq5:76-139`
  — one-symbol `CopyRates`/OLS/OU fit;
- same file `:175-220` — one `QM_EntryRequest`, with no second leg, hedge ratio,
  cointegration/spread construction, or atomic package lifecycle.

Named fix: implement the approved cointegrated two-leg spread package and its
hedge ratio/atomic lifecycle, or obtain an OWNER-approved card revision that
explicitly authorizes a univariate OU strategy. Do not silently rescope it.

### 2. The adaptive time stop ignores fitted half-life

The card requires force-close after `2.5 * tau` bars (`cards_approved/...md:99`).
The EA uses the configured upper bound for every trade:

`framework/EAs/QM5_37001_ernest-chan-ornstein-uhlenbeck-statarb/QM5_37001_ernest-chan-ornstein-uhlenbeck-statarb.mq5:270-275`

Specifically, line 274 calculates
`strategy_time_stop_mult * strategy_max_half_life`, so fitted half-lives of 5
and 40 bars both get the same 100-hour stop. Named fix: bind/persist the fitted
entry `tau` for the owned position and evaluate the time stop against
`strategy_time_stop_mult * entry_tau`, with restart-safe reconstruction.

### 3. Three card loss-limit contracts are absent

The card requires a 2.0% daily realized-loss entry halt
(`cards_approved/...md:87`), a 2.5% daily hard stop, and a 5.0% total-drawdown
stop (`:112-113`). The EA declares/wires none of them. The current common-chain
default is instead `QM_KillSwitchInit(..., 3.0, 0.0, 1.0)`
(`framework/include/QM/QM_Common.mqh:296-298`), which is neither the card's
daily thresholds nor a 5% total-drawdown stop.

Read-only command:

```powershell
python tools/strategy_farm/build_gate_hardening.py --repo-root . --ea-label QM5_37001_ernest-chan-ornstein-uhlenbeck-statarb
```

The returned `qm.build-gate-hardening/v1` JSON contains exactly three failures:

- `daily_entry_halt=2% ... matching input is absent`;
- `daily_hard_stop=2.5% ... matching input is absent`;
- `total_drawdown_stop=5% ... matching input is absent`.

Named fix: expose and wire the approved card thresholds through the governed
framework kill-switch path, keeping the daily entry halt distinct from the
hard liquidation/total-DD controls.

### 4. Entry-only filters can suspend protective exits

The card locates its no-trade filters in `STATE_IDLE`
(`cards_approved/...md:83-88,120-127`). The EA returns on rollover/spread at
source lines 334-335 before it evaluates the strategy exit at lines 339-351.
An open position can therefore miss mean-reversion, structural-break, or time
exits during a rollover/spread blackout. Named fix: keep management/protective
exits reachable for owned exposure and apply the no-trade filter only to new
entry evaluation.

### 5. Closed-bar OLS is recomputed on every open-position tick

`Strategy_ExitSignal` invokes the full lookback OU calculation at source line
253, which calls the 101-bar `CopyRates` plus two lookback loops at lines
89-128. `OnTick` calls that exit at line 339 before its new-bar gate at line
361. The raw-series access has the required `perf-allowed` annotation and a
successful-count bound at line 89, but the call placement still repeats the
full H1 fit on every tick while a trade is open. Named fix: cache one OU result
per completed H1 bar and consume that bounded closed-bar result for exits.

### 6. Rollover blackout is not driven by simulated broker time

The strategy uses `TimeGMT()` directly at source lines 142-149. This does not
derive the card's GMT window from the broker/tester clock and was already
identified in the prior cross-review. Named fix: convert `TimeCurrent()` with
the governed broker-to-UTC helper (`QM_BrokerToUTC`) before applying the
23:55-00:05 GMT window.
