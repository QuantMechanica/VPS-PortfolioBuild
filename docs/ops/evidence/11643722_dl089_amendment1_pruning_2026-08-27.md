## Implemented behavior

`opt_census_pruning.py` validates the amendment and ledger invariants, reads a
reconciled measured report, and applies the strict trigger
`entry_trading_days < 10`. For the same declared arm it dispositions only
unclaimed `pending` rows whose calendar year is greater than the trigger year.
It never stops or rewrites an `active` row.

Each disposition is an append-only, exclusive-create JSON receipt under the
ledger's `pruning_receipts/` directory. It records the skipped `cell_key`,
trigger `cell_key`, arm, trigger/skipped years, measured entry-day count,
activity floor, declared count, amendment binding, and timestamp. The work item
becomes `done/SKIPPED_EXCLUDED`; its payload retains a receipt path and SHA-256.
Existing receipt identity collisions fail closed.

The check is installed at all normal dispatch boundaries:

1. after an `OPT_CENSUS` row is durably classified `done/MEASURED`, later
   pending years are dispositioned in the same database transaction;
2. immediately before a resident terminal-worker claim, as a restart/backfill
   backstop;
3. immediately before the legacy secondary dispatcher's claim CAS.

The selector authenticates skip receipts and treats a skipped year as a missing
arm year. Existing selection code therefore makes the arm inadmissible without
altering its consistency, ranking, quorum, or walk-forward rules. The governed
matrix service accepts both `MEASURED` and authenticated exclusion dispositions
as resolved rows at final closure. Lifecycle and clean-view vocabularies map
the new disposition to terminal measurement-family resolution, never a gate
pass or economic result.
