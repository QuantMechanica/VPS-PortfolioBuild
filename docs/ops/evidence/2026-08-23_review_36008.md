## Confirmed defects

### 1. High — card TP1/break-even/runner lifecycle collapsed to a single signal exit
Card §3.4 requires TP1 at +1.0*ATR closing 50% volume and moving SL to
break-even, then a runner to the KAMA/Vortex opposite-cross exit.
- `req.tp` set to `0.0` at L242 and never reassigned (only `req.sl` at L277/L283);
  no broker TP.
- `Strategy_ManageOpenPosition()` (L296-298) is an empty stub — no partial close,
  no break-even move.
- Only the all-or-nothing opposite-cross exit (`Strategy_ExitSignal`, L300-347)
  exists. The approved two-stage payoff structure is silently reduced. Same defect
  class remediated on siblings QM5_36001/36004.

### 2. Medium — kill-switch / loss-limit contract not wired to card values
EA calls `QM_KillSwitchCheck()` (L392) but never `QM_KillSwitchInit` with card
values, so it inherits the framework default `QM_Common.mqh:298`
(`QM_KillSwitchInit(ea_id, magic, 3.0, 0.0, 1.0)` → daily 3.0%, portfolio DD
disabled). Card §4.2 wants daily 2.5% / total 5.0%; the §3.1.3 daily 2.0%
realized-loss no-trade condition is also absent from `Strategy_NoTradeFilter()`
(L218-235 check only spread + rollover). Approved drawdown contract not enforced.

### 3. High — OnTick ordering gates protective exits behind the entry filter
`OnTick` L401 `if(Strategy_NoTradeFilter()) return;` runs before
`Strategy_ManageOpenPosition()` (L404) and `Strategy_ExitSignal()` (L406). During
a spread spike (>1.8*ATR) or the 23:55-00:05 rollover blackout an already-open
position is neither managed nor exited — the no-trade gate (entry governance)
also suspends protection of open positions. Reorder manage/exit before the
no-trade gate.
