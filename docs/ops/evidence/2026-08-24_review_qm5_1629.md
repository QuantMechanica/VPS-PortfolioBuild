## Verdict: RECYCLE (named actionable defects; do not promote to Q02/PIPELINE)

Independent read of the `.mq5` against the approved card confirms the prior mandatory
review (`docs/ops/evidence/2026-08-23_qm5_1629_gemini_code_review.md`, REQUEST_CHANGES).
The binary compiles clean and passes hardening, but does not faithfully mechanize the
approved card. Findings verified against source, most-severe first:

### 1. HIGH — smoother uses median price, card mandates close (strategy identity)
`ComputeCyberneticCycle` feeds `(high+low)/2` into the 4-bar weighted smoother
(`QM5_1629_ehlers-cybernetic-cycle-h4.mq5:81-84`). The card pseudocode is explicit:
`smooth[t] = (close[t]+2*close[t-1]+2*close[t-2]+close[t-3])/6`, and R2 names `iClose`.
Median vs close produces different waveforms, zero crossings, amplitudes and therefore
different entries/exits — a strategy-identity deviation, not an implementation detail.
Fix: use completed H4 close, then rebuild and rebind identities.

### 2. HIGH — 20-bar time stop implemented as wall-clock seconds
`Strategy_ExitSignal` tests `TimeCurrent() - opened >= strategy_time_stop_bars * h4_seconds`
(`:285`). Card requires exit after 20 H4 **bars**; elapsed-seconds counts weekends/holidays,
so a Friday position can hit the threshold with far fewer completed bars. Fix: count actual
H4 bars from the open bar (fail-closed on history error).

### 3. HIGH — break-even move omits the card-required spread offset
`Strategy_ManageOpenPosition` calls `QM_TM_MoveSL(ticket, open_price, "MOVE_TO_BE")`
(`:268`) — raw open price. Card §Exit: "move SL to break-even-plus-spread". As written the
protected exit can net a loss after costs. Fix: apply direction-correct spread offset and
validate against broker stop constraints.

### 4. MEDIUM — H4 execution scope not enforced in the binary
Bar gating uses `QM_IsNewBar()` with default `PERIOD_CURRENT` (`:402`); no `_Period==PERIOD_H4`
guard. Setfiles pin H4 so live/backtest dispatch is H4, but the binary does not fail closed on
a wrong chart. Fix: reject non-H4 init or gate the clock explicitly to `PERIOD_H4`.

### 5. LOW/MEDIUM — cooldown state advances before order confirmation
`g_last_trade_time`/`g_last_trade_dir` are set inside `Strategy_EntrySignal` (`:229-230`)
before `QM_TM_OpenPosition` (`:412`) returns; a broker/stress/risk rejection still arms the
4-bar cooldown. Fix: update cooldown only on confirmed entry.
