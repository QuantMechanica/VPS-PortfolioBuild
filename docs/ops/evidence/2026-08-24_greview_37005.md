## Actionable defects

### 1. The EA invents a fixed 1R take-profit when the approved midline target is invalid

The approved exit is exactly the 20-period SMA/Bollinger midline
(`card:95-97`). For longs, the EA instead substitutes `ask + sl_dist` whenever
the midline is not above the current ask (`.mq5:143-150`); shorts similarly use
`bid - sl_dist` when the midline is not below the bid (`.mq5:152-159`). That is
an unapproved fixed 1R payoff and changes the strategy measured at Q02.

Named fix: reject an entry whose approved midline TP is already invalid at the
live entry quote, or obtain an OWNER-approved fallback rule. Do not silently
replace the card's exit mechanism.

### 2. All three approved loss-limit controls are absent

The card requires a 2.0% daily realized-loss entry halt (`card:82-87`), a 2.5%
daily hard stop, and a 5.0% total-drawdown stop (`card:109-112`). The EA has no
matching strategy inputs or executable checks (`.mq5:21-53,91-107,183-201`).
Its generic framework initialization currently installs 3.0% daily and 0.0%
portfolio drawdown defaults (`framework/include/QM/QM_Common.mqh:296-299`),
which do not satisfy the card.

The fresh target-specific `build_gate_hardening.py` invocation independently
reported three `EA_CARD_LOSS_LIMIT_MISMATCH` failures: `daily_entry_halt=2%`,
`daily_hard_stop=2.5%`, and `total_drawdown_stop=5%` all lack matching source
inputs.

Named fix: wire all three exact card controls through the governed entry/kill-
switch paths, or obtain an OWNER-authorized card correction before rebuilding.

### 3. The approved three-tick slippage cap is not wired

The card caps market-order slippage at 3.0 ticks (`card:109-112`). The EA
declares no deviation control and calls only `QM_FrameworkInit` (`.mq5:183-201`).
The framework therefore invokes its entry path with the default 20 deviation
points (`framework/include/QM/QM_Common.mqh:296-297`;
`framework/include/QM/QM_Entry.mqh:63-88`), which is applied to each request at
`QM_Entry.mqh:452-463`.

Named fix: convert three symbol ticks to the framework deviation-point unit and
configure that value through the governed entry configuration path while
preserving the news, stress, and resolved host-magic bindings.

### 4. The raw rates array lacks the ticket-required annotation and explicit size guard

`Strategy_EntrySignal` uses a dynamic `MqlRates rates[]`, calls `CopyRates`, and
then indexes `rates[0]` (`.mq5:129-144,152-153`). The call is bounded to one bar
and its return count is checked, so the general D10 analyzer accepts it, but the
review ticket explicitly requires an `ArraySize` guard and forbids raw-series
reads without a `perf-allowed` annotation. Neither appears at this use-site.

Named fix: use a framework closed-bar helper, or retain the bounded read with a
recognized `perf-allowed` justification and fail closed unless both the copy
count and `ArraySize(rates) >= 1` are proven before indexing.
