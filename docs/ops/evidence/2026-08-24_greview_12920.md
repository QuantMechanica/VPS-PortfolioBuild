## Blocking findings and named fixes

### 1. Friday close contradicts the mandatory D0 exit

The card requires the position to close at election-day close and calls that time stop mandatory (`D:/QM/strategy_farm/artifacts/cards_approved/QM5_12920_qp-pre-election-sp500.md:44-50`). The EA defaults `qm_friday_close_enabled=true` (`framework/EAs/QM5_12920_qp-pre-election-sp500/QM5_12920_qp-pre-election-sp500.mq5:36-38`), passes it into the framework (`...mq5:219-234`), and executes the handler before strategy exit (`...mq5:266-274`). The backtest setfile does not override the Friday-close inputs (`framework/EAs/QM5_12920_qp-pre-election-sp500/sets/QM5_12920_qp-pre-election-sp500_SP500.DWX_D1_backtest.set:17-24`). A D-5 position therefore reaches Friday before D0 and can be closed early.

Named fix: make Friday close disabled for this card-faithful strategy and bind that value in the governed setfile; do not add a new exit mechanic to the card.

### 2. The election entry is neither exact-once nor restart-safe

The card authorizes entry only at the D-5 close (`card:38-42`). The implementation instead admits every D1 bar after D-5 through D0 (`...mq5:157-160`). Its only cycle latch is process-local `g_last_traded_election_year` (`...mq5:48`), while `OnInit` performs no reconstruction (`...mq5:217-239`), so a restart can forget a filled cycle and open again later in the window. Conversely, the latch is consumed before the framework order call (`...mq5:183-184` versus `...mq5:295-300`), so an order rejection can suppress the only legitimate opportunity.

Named fix: gate entry to the exact first tradable D-5-close transition, reconstruct the cycle from durable owned-position/deal history during initialization, and consume the cycle only after a confirmed successful open (with idempotent restart behavior).

### 3. Entry-only controls can suppress the mandatory time exit

The card's D0 time stop is mandatory (`card:44-50`), but `OnTick` returns on the news filter, Friday handler, and no-trade filter before it evaluates `Strategy_ExitSignal` (`...mq5:254-274`). The news filter is wired, but its current placement can delay the D0 close; the Friday handler can replace it with an earlier close. This is a card-fidelity defect, not merely an economic Q02 question.

Named fix: keep kill-switch/MAE safety behavior, but execute owned-position management and the mandatory D0 exit before entry-only news/no-trade admission checks; disable the unauthorized Friday exit for this EA.
