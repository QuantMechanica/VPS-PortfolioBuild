## Card-faithfulness (the blocking failures)

The card is titled "Alpha Architect **Volatility-Sorted** MA Timing" and its Mechanik
requires: compute trailing 12-month realized vol **for each instrument**, rank into
quintiles, admit only the **highest-volatility quintile**, then apply a **10-month
(month-end) SMA** timing signal; exit when close <= SMA10M **or the sleeve leaves the
high-vol quintile**. Both defining features are missing from the delivered EA.

- **RECYCLE-1 (critical): volatility-sorting does nothing.** The strategy's namesake is
  inert. `Strategy_CalculateRealizedVol(_Symbol, ...)` is called once
  (`QM5_9166_aa-vol-ma-timing.mq5:223`) and its result is used only as a presence gate
  `if(realized_vol <= 0.0) return false;` (`:224`). There is no cross-symbol snapshot,
  no ranking, no quintile selection, no minimum-universe fallback, and no
  quintile-exit — grep for cross-symbol iteration / rank / quintile returns nothing.
  Every independently attached symbol whose MA condition is true can enter. The card's
  central selection mechanism is not implemented, and the exit "leaves the quintile"
  branch is impossible.

- **RECYCLE-2 (critical): wrong SMA basis.** Card defines `SMA10M = average(last 10
  completed month-end closes)`. EA computes `QM_SMA(_Symbol, PERIOD_D1,
  strategy_sma_months*21, 1)` = a 210-**session daily** SMA
  (`:217-218` entry, `:280-281` exit). No MN1 / month-end read exists. Daily weighting
  of variable-length months changes the signal; this is not the approved fixed monthly
  series.

The SPEC.md silently re-scopes the strategy to a per-symbol "long/cash trend-following"
(§5: "2-6 trades/yr", "Monthly rebalanced long/cash trend-following on D1"), dropping
the cross-sectional volatility sort. The card, not the SPEC, is the approved authority,
so the narrowing is itself a card-conformity defect.

## Robustness defects (also actionable, not blocking on their own)

- **RECYCLE-3 (high): monthly opportunity consumed before trade success.**
  `g_last_entry_rebalance_key = rebalance_key` is set inside `Strategy_EntrySignal`
  (`:238`, `:254`) **before** `OnTick` calls `QM_TM_OpenPosition`; any broker/stress/
  governor/risk rejection burns the only monthly entry. Same for
  `g_last_exit_rebalance_key` (`:288`, `:294`), set before the close loop runs — a single
  rejected close blocks all further exit attempts that month. Both keys are also
  restart-volatile (module globals, not persisted). Advance state only from confirmed
  trade evidence; allow risk-reducing close retries until flat.

- **RECYCLE-4 (medium): entry filters suppress the exit path.** In `OnTick`, the news
  gate and `Strategy_NoTradeFilter()` (wrong-timeframe / warmup / spread) `return`
  **before** `Strategy_ExitSignal()`. A news blackout or wide/invalid spread leaves an
  open position unmanaged on its MA-timing exit. (Catastrophic protection survives via
  `QM_KillSwitchCheck` and the broker-side ATR SL, so this is a management-timing defect,
  not an uncapped-risk defect.) Keep strategy/framework risk reduction independent of
  new-entry admission filters.

- **RECYCLE-5 (medium): spread guard fails open.** `Strategy_SpreadAllowsEntry` returns
  true when `ask<=bid`, current spread rounds to 0, or median <= 0, and
  `Strategy_MedianSpreadD1` accepts any positive partial `CopyRates`. Invalid/incomplete
  evidence becomes a pass. Require 20 valid completed-D1 observations, positive bid/ask
  ordering, and a positive median.
